API 速查

全部公开方法，签名对照源码。示例用 Java，Kotlin 直接调用即可。

01

QingzhuSdk 门面

静态方法，进程内单例。重复初始化幂等。

方法作用
init(Context)初始化内核与适配器，注册 Eddystone 与 Generic 两个开源协议
registerProtocol(ProtocolPlugin)注册协议插件，重复注册同一 id 幂等；注册后立即触发 install()
getProtocols()当前已装配的协议 id 列表
startScan(ScanListener)开始扫描，默认参数
startScan(ScanOptions, ScanListener)带过滤条件的扫描
stopScan() / restartScan()停止 / 重启扫描
setScanStateListener(ScanStateListener)监听扫描开关状态
createTask(String mac)新建任务。会先删除该设备已有任务
createTask(QDevice)用扫描到的设备建任务，同样先删后建
getTask(String mac)只查询，没有返回 null
deleteTask(String mac)取消、断开、从任务池移除
observeAll(Object owner, TaskListListener)观察全部任务，注册后立即推一次全量快照
snapshots()当前所有任务的不可变快照列表
setMaxConnections(int)并发连接数。0 = 用体检建议值，1-N = 手动固定
setMaxTransfers(int)传输窗口。1 = 串行，N = 最多 N 台同时发
setMaxRetries(int)失败重试次数，默认 3
setMaxPendingIntents(int)每设备指令队列上限，默认 10000；0 = 忙碌时直接失败
setConnectCallbackTimeoutMs(long)系统连接回调兜底，默认 20 秒
getConcurrency()当前生效的并发容量
settings()全局设置中心，含协议声明的可配置项
02

QTask 任务

一台设备一个任务。所有读写方法都可随时调用。

方法说明
send(QCommand, TaskCallback)发命令。被接收就恰好回调一次；队列满回调 BUSY
connect(TaskCallback)连接并保持。已连接时立即回调成功
disconnect()真正断开，任务保留
setConnectParams(Map)设置连接参数，对该任务之后的所有连接生效
observe(Object, TaskObserver)观察本任务，回调不可变快照
cancel()中止当前操作，回到操作开始前的链路状态，任务保留
delete()取消 + 断开 + 从任务池移除
id()任务 id。清理时用它判断是不是自己那个任务
deviceMac() / currentMac()任务绑定的 MAC / 当前实际连接的地址
getDevice()扫描解析出的设备，未找到时为 null
getState()当前状态，见枚举
getOutcome()最近一次命令的终态分类
getResult()设备回执，可能为 null
getError()最近一次失败原因
getProgress() / getSentBytes() / getTotalBytes()发送进度与字节数
pendingIntentCount()待办队列里还有几条
isDeleted()是否已被删除
反复进出页面时用 createTask。旧页面的销毁可能晚于新页面启动，用同一个任务会互相干扰。清理时带 taskId 只删自己那个。
03

QCommand 命令

用 Builder 构造。keepConnected() 与 disconnectAfter() 互斥。

方法说明
connect()只连接，不发送
send(String json)发文本 JSON
send(String json, byte[] data)JSON + 单块字节
send(String json, Map attachments)JSON + 多附件，大块数据走这里
keepConnected()发完保持连接
disconnectAfter()发完明确断开，优先于任务的保持期望
noAck()标记无需应答。目前只是标记，未传给底层
reconnect(ReconnectPolicy)意外断开后的重连策略，默认关闭
build()两个互斥项同时出现时抛 IllegalStateException
发完断不断的判断：命令没有声明 disconnectAfter，且任务上有保持期望或命令声明了 keepConnected 时，保持连接。
04

TaskResult 命令结果

每条被接收的命令回调一次。

方法说明
isSuccess()判断成功的唯一依据
payload()设备回执，成功也可能为 null
error()失败原因
stage()失败发生在哪一步，见 TaskStage
05

枚举

类型取值
TaskStateUNKNOWN READY SEARCHING QUEUED CONNECTING CONNECTED SENDING
TaskOutcomeNONE SUCCEEDED CONNECT_FAILED OPERATION_FAILED CANCELLED
TaskStageSEARCH CONNECT SEND CANCEL DELETE BUSY CLOSED
没有 FAILED 状态。失败后任务回到 READY 或 UNKNOWN，失败原因看 error 与 stage。
